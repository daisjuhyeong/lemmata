## Defects, most severe first

**D1, High: blocked font request in the VS Code tab; e2e fails 6/7 (5 regressions).**
- The tab inlines only the serif fonts: `TAB_FONTS = /^SourceSerif4-/` (`vscode/src/core/embed.ts:10`, `vscode/src/tab.ts:86-89`).
- So the inlined `fonts.css` keeps `@font-face … url(fonts/SourceSans3-Variable.woff2)`. `tokens.css:26` puts `"Source Sans 3"` first in `--font-sans`, so the page requests that file. The tab CSP (`font-src data:`) blocks it, logging `Loading the font 'http://lemmata.test/fonts/SourceSans3-Variable.woff2' violates … "font-src data:"`.
- It fires once on the first open, even with VS Code-style `--vscode-font-family` set on `<html>` (where the body correctly uses the editor font). So it would most likely show in a real VS Code console too, not just the harness.
- No visible damage, because the fallback is the editor font. But every e2e test asserts a clean console, and the `errors` array is shared, so one message fails every later test.
- `vscode/test/unit/s18.test.ts:73` asserts that this URL stays in the tab's CSS, which locks the bug in.
- Possible fixes, the builder's call: drop the sans `@font-face` from what the tab receives, or keep `"Source Sans 3"` out of the tab's font stack before first paint.
- Diagnostic only: with that one message filtered in a scratch copy of the compiled test, 7/7 pass.

**D2, Medium: readable text below 4.5:1, a decision for Juhyeong.** These are the reference site's own colours (`tokens.css:11-12, 15, 19`):
- Band title and nav, `--bg` on `--accent`: 2.93. This fails even the 3:1 large-text threshold for the 32 px bold title.
- Band subtitle, `--accent-pale` on `--accent`: 2.17.
- Footer state line, `--muted-light`: 2.65 (`app.css:528`).
- Tags and captions, `--muted`: 4.27 on `--bg`, 3.81 on `--bg-2`.

The builder's proposed fix checks out:

- A band of #5e7a70 gives 4.54.
- Keeping the band and setting its text in `--text` gives 5.77.
