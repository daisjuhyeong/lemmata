개발 환경: 혼자서, 에이전트 팀과

나: 방향, 설계 결정(ADR), main 병합, 외부 게시
└─ Claude Code 메인 세션  (Mac mini M2, 상시 가동, Max 플랜)
   ├─ CTO, PM, 디자이너, QA(독립 검증)
   ├─ 엔진 개발, 앱 개발, 리서치, 그로스
   └─ LLM-wiki (git)
      ├─ decisions/   ADR
      ├─ research/    인터뷰, 설문
      └─ sprints/     작업 카드, 인계 노트

Mac mini M2 한 대

항상 켜 두고 Claude Code를 Max 플랜으로 실행. 휴대폰, 노트북에서 Remote Control과 SSH로 지시

안전장치

OS 샌드박스, 허용한 도메인만 통신, main 브랜치는 내 승인 없이 바뀌지 않음

실패를 줄이는 규칙

멀티에이전트 실패율 41–86.7% (MAST). 완료 조건이 있는 작업 카드, QA 독립 검증, 인계 노트 없으면 미완료

출처: Cemri et al., MAST (NeurIPS 2025) / LLM-wiki 패턴: Karpathy(2026.4)

19

개발 환경입니다. 혼자 하는 프로젝트라서 Claude Code 에이전트를 팀처럼 씁니다. Mac mini 한 대를 항상 켜 두고 메인 세션이 일을 나누고, 그 아래 CTO, PM, 디자이너, QA 같은 역할별 에이전트가 있습니다. 모든 결정과 인터뷰, 작업 기록은 git으로 관리하는 LLM-wiki에 남깁니다. Mac mini는 모델을 돌리는 게 아니라 에이전트가 일하는 사무실 역할이고, 저는 휴대폰이나 노트북에서 원격으로 지시합니다. 멀티에이전트는 실패율이 높다는 연구가 있어서, 작업 카드와 독립 검증, 인계 노트를 규칙으로 정했고, 설계 결정과 병합은 반드시 제가 합니다.
